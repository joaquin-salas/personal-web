How Raft keeps a cluster in agreement

March 2026

Raft splits consensus into three smaller problems: electing a leader, replicating the log, and keeping everything safe when machines crash. I wanted to understand each one well enough to build it, so this is what I learned along the way.

Leader election

Every node starts as a follower. If it hears nothing from a leader before its electionTimeout fires, it becomes a candidate and asks the others for votes. The original paper randomises that timeout so two nodes rarely run at once.

// startElection turns a follower into a candidate and asks for votes.
func (n *Node) startElection() {
	n.term++
	n.state = Candidate
	n.votedFor = n.id
	votes := 1

	for _, peer := range n.peers {
		go n.requestVote(peer, n.term)
	}
	log.Printf("node %d: election for term %d", n.id, n.term)
}
